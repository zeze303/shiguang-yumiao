# 拾光育苗 UI 设计规范 v1.0

交付日期：2026-10-12。载体：微信原生小程序。母品牌：心迹成诗。品牌口号：成长有迹，心自成诗。

配套文件：`prototype.html` 为可离线打开的交互设计稿；`page-spec.md` 为逐页布局、交互与状态；`README.md` 为预览与验收指南。所有姓名、学校与分数均为虚构演示数据。此交付不修改现有后台或接口。

## 1. 设计方向与边界

采用“暖纸成长手册”：用米白纸面、低对比边界、暖底与留白组织内容；红色承担主行动，金色承担成长仪式。乡野、幼苗、落叶与纸风筝以少量手绘线条出现，不铺满整个工具界面。孩子档案先看具体观察，再看 AI 建议，最后记录陪伴。管理端使用更紧凑的指标卡与预警列表。

比较过的三个方向：

| 方向 | 核心思路 | 落地难度 | 适合场景 | 取舍 |
|---|---|---|---|---|
| 乡野绘本 | 插画场景串联成长故事 | 高：需要成套插画与压缩资源 | 品牌宣传、儿童阅读 | 首屏信息效率偏低 |
| 成长仪表盘 | 指标、预警、筛选占主导 | 低：标准卡片与图表 | 管理决策、批量查看 | 日常陪伴的温度较弱 |
| 暖纸成长手册（采用） | 轻卡片、手绘点缀、行动导向 | 中：统一组件与少量封面资源 | 志愿者陪伴，兼容管理 | 诗页保留仪式感，工具页控制装饰 |

不增加公开社区、支付、孩子账号、心理诊断或排行榜。志愿者只能看到自己结对的孩子；管理可见全部。管理详情不显示“以志愿者身份记录”入口。诗歌分享默认匿名，排除学校、成长分数、监护人信息与记录照片。

## 2. 设计尺寸与微信结构

### 2.1 基准

设计画布为 **375 × 812 CSS px**，对应宽度 **750rpx**。基准转换为 `1px = 2rpx`，只在 375px 宽设计稿上成立；实际设备按 `px = rpx × windowWidth / 750` 换算。布局尺寸优先 rpx，状态栏、胶囊、安全区采用设备返回的 px。

| 区域 | 原型尺寸 | 原生实现 |
|---|---:|---|
| 状态栏 | 44px / 88rpx 示意 | 系统管理，不能将 44px 硬编码到所有设备 |
| 顶部导航 | 44px / 88rpx 示意 | 优先原生默认导航，背景 `#fdf8f0`，文字 black |
| 微信胶囊 | 87 × 32px 示意 | 官方提供，不自绘、不劫持、不添加业务按钮 |
| 内容宽度 | 375px | 自适应设备宽度 |
| 左右边距 | 16px / 32rpx | 窄屏可缩为 12px / 24rpx |
| 标准卡片宽度 | 343px / 686rpx | `width: auto`，不硬编码 |
| tabBar 业务高度 | 50px / 100rpx 示意 | 自定义 tabBar 50px + 实测底部安全区 |
| 底部安全区 | 34px 示意 | `screenHeight - safeArea.bottom`，或系统支持的 `env(safe-area-inset-bottom)` |
| 次级底部操作区 | 12px + 44px + 34px = 90px | 实际为 12px + 按钮至少44px + 安全区 |

四项 tabBar 分别占 25% 宽，图标 23px，文字 10px/16px；图标与文字间距 2px。全项热区至少 44px 高。考虑两套不同 tabBar 结构，**推荐微信 `custom-tab-bar`**：从服务器登录结果读取角色后渲染四项，使用 `wx.switchTab` 导航；所有顶级路由登记在 `app.json`。切换角色演示是 HTML 外部设计工作台能力，正式小程序不显示角色切换按钮。若采用两套分包或两个入口架构，应由工程团队另行定稿。

次级页面不显示 tabBar，用左上返回 + 底部操作区或安全区收尾。详情返回保持来源列表筛选和滚动位置。首页顶部品牌仅在内容区域出现，导航标题保持短而明确，不延伸进胶囊。

优先使用原生导航。若确实使用 `navigationStyle: custom`，应以 `wx.getWindowInfo()` / `wx.getMenuButtonBoundingClientRect()` 计算状态栏和胶囊：导航高度可按 `capsule.height + 2 × (capsule.top - statusBarHeight)` 推导，总顶区为状态栏加导航高度。异常返回时使用经实机校验的回退，不猜测胶囊坐标。原型的系统栏与胶囊只是比例参考。

页面允许纵向滚动；列表不嵌套同向滚动容器。固定操作区与内容分离，内容末尾留足空间，键盘打开时输入框可见，操作按钮不遮挡输入。参考宽度 320 / 375 / 390 / 430px；横屏按设备能力处理，不通过缩放整个界面适配。大字模式可换行，按钮与卡片高度随文本增加。

### 2.2 间距与栅格

基础步长 4px / 8rpx。

| 令牌 | px | rpx | 用途 |
|---|---:|---:|---|
| space-1 | 4 | 8 | 图标与短标签、小字行间 |
| space-2 | 8 | 16 | 标签间距、正文与辅助文案 |
| space-3 | 12 | 24 | 卡片之间、列表行内元素、按钮间距 |
| space-4 | 16 | 32 | 页面边距、卡片内边距 |
| space-5 | 20 | 40 | 页头与列表、诗卡正文留白 |
| space-6 | 24 | 48 | 章节间距、弹层内边距 |
| space-8 | 32 | 64 | 重点分组间距 |

标准内容宽 343px；双列指标间隙 12px，列宽 `(343-12)/2 = 165.5px`。三列上传区间隙 10px，每格约 107.7px 宽、92px 高。四维微柱四等分，间隙 10px，列宽约 68.25px。四维卡中的分数与标签不截断。

## 4. 字体与层级

工具界面使用系统中文无衬线字体：iOS PingFang SC，Android 系统字体；原型退到 Microsoft YaHei。诗歌标题、诗正文和品牌可用系统宋体。原生设备没有合适宋体时，界面退回系统字体，分享图片使用 Canvas 合法字体资源或固定文字渲染；不强依赖在线字体，不通过小字号营造“精致”。

|---|---|---|---|---|
| Display-number | 30 / 42 | 60 / 84 | 600 | 管理指标 |

| Action / Item | 15 / 24 | 30 / 48 | 600 | 按钮、记录标题、菜单 |
| Body | 14 / 24 | 28 / 48 | 400 | 状态解读、表单文本 |

| Metadata | 11 / 18 | 22 / 36 | 400 | 标签、维度、图表刻度 |

## 6. 组件规格

### 6.1 孩子卡 ChildCard

全卡可点，纸面、16px圆角、16px内边距；卡之间12px。头部48px昵称头像，右侧状态标签；姓名17px/25，年级与学校12px/20。头部元素间距12px。四维微柱距头部16px，标签11px、分数11px，柱高4px。底部分隔距图表16px，底栏上留12px；记录日期、结对人或周期11px/18，箭头16px。内容自然增高，375px基准约174–186px，不能为固定高度裁切文字。

状态优先级：有单维 `<40` 显示“需跟进”并在档案说明“优先人工跟进”；有单维 `<60` 显示“需跟进”；其余显示综合等级。后台等级值保持原词汇；列表不在孩子名字旁直接展示“高危儿童”等身份化称呼。正式接口的预警信号优先于前端推导。

加载用等比例骨架；空列表含手册幼苗插画、一句说明与下一步；失败保留导航，错误区常驻并可重试。图片头像缺失用昵称末字手绘底纹，不用真实儿童肖像占位。

### 6.2 按钮 Button

主按钮：主红底、米白字、15px/24px 600、至少44px高、左右16px、圆角12px。次按钮：透明底、深红字、深红30%边界。轻按钮：主红7%背景、深红字。危险操作：深红文字，二次确认中使用清晰动作文案“解除结对”。禁用透明度0.45且禁点击；正式版应检查背景与文案可辨识度。

轻量筛选：视觉高36px，字号12px，左右12px，18px圆角，选中深红底米白字。实现时外包至少44px点击热区；原型保留36px视觉尺寸。文字动作12px，热区44px，箭头16px。主按钮点击后立即禁用并改文案，成功返回结果，错误保留输入并恢复按钮。

### 6.3 标签 Tag / Notice

标签最少24px高，左右8px、上下2px、字号11px/18；预警用红色浅底深红字加警示SVG；AI标签用紫色浅底紫字。提示条12px内边距、12px圆角、图标18px、间距8px，正文12px/20。系统关键错误用常驻错误区，不用1.8秒toast承载唯一错误信息。

### 6.4 表单 Form

输入与选择高至少46px、内边距12px、字号14px/22、10px圆角、1px边界。Label14px600，距控件10px。字段之间22px（44rpx）。文字域最小174px；记录正文10–1000字为本版UI默认约束，待接口与内容安全规则对齐。剩余字数在字段下方右对齐。错误文字12px深红，紧贴字段6px，并将焦点/滚动定位到错误字段。已有文字与图片保持不变。

陪伴方式2×2，每格至少48px高，边界与文字一起标记选中。图片三列，每格92px高，间隙10px；最多3张、每张5MB为本版默认值。上传中每张有独立进度；失败仅重传对应图，删除热区至少44px（原型示意32px可视角标，正式版扩热区）。获取图片仅由用户点击触发 `wx.chooseMedia`；取消不报错。压缩后上传，提交时传服务端返回的URL，不传本地临时路径。

### 6.5 图表

雷达图：卡宽343px，内宽约309px；SVG设计逻辑画布300×232。四轴固定顺时针：心理（上）、美育（右）、财商（下）、行为（左）；刻度0–100，网格20分一步。网格用文字色12%透明度、0.8px；总体轮廓主红1.8px、填充10%；顶点按四维色3.3px。数值同时以卡底四列呈现，不只依赖图形。无数据为“暂无观察”，不伪装成四个零。

趋势图：单维切换，四维固定配色，y轴固定0–100；0/50/100三条网格；x轴显示实际周期；线宽2.4px、节点半径4px，节点热区至少30px，实机可扩大到44px。原型近四期曲线为虚构演示，不从当前分数推导正式历史。正式版来自 records 接口，缺期留空或断线，不补零，不用平滑曲线产生超范围峰值。切换不重置整页滚动；点击节点显示周期和分数。财商曲线增加深色外描线或形状以提高浅金可见性，图例文字用深色。

等级分布用横向条形图，标签、人数、百分比同时可读；0人保留一行，不画伪最小柱。人数总和与总览总人数一致。禁止以综合均分推导单维预警人数。

原生小程序不直接把HTML内联SVG放入WXML。图标可导出SVG资源后验证 `<image>` 支持，稳定方案导出PNG双状态或用Canvas绘制；图表采用Canvas 2D或小程序兼容图表库。计算使用设备像素比，避免图像发虚。图表提供文本替代数据。

### 6.6 成长诗与分享卡

诗列表封面128px高，阅读封面185px高，分享预览封面154px高。展示用 `aspectFill` / cover，中心保留主体，图片中不生成标题或长文。标题由文本层叠加，避免AI图像中文字错误。

正式封面应来自 `cover_url`，原型SVG只示意红金乡野、幼苗、纸风筝。封面缺失、生成失败或URL过期时使用本地品牌插画，不阻断诗文阅读。标识分开：原型“AI生成诗文 / 封面设计示意”；正式AI封面成功后“诗文与封面由AI生成”。

推荐封面提示词模板：米白纸底，中式温暖手绘，乡间秋日、微光、幼苗和纸风筝，低饱和红金点缀，大量留白，不出现可识别儿童肖像，不含文字、学校标志或个人信息，横向构图。配色合规仍需出图后人工选图或品牌色蒙版，提示词不能保证准确色值。

分享默认内容：诗名、诗文、匿名称谓、品牌、口号、AI标识。昵称默认关闭；可显式开启，分享前确认适用授权。原型可下载自包含SVG；正式版Canvas导出PNG（建议750px宽），长诗自动增高或分页，不裁掉末行，不能把HTML下载逻辑直接照搬。

保存路径：`wx.canvasToTempFilePath` → 用户点击保存 → `wx.saveImageToPhotosAlbum`。拒绝相册权限时保留预览，说明如何在设置中授权，并提供返回；不要自动连续弹授权。此版未设计真实小程序码，若加入，使用后端获取的有效小程序码，不用装饰二维码误导。

### 6.7 空态、加载、错误、弹层

空态插画120×105px，标题18px/28、说明13px/23、说明下24px主按钮；内容区上留64px。搜索无结果用32px顶部留白与“清除筛选”。

列表加载使用卡片骨架；一次只保留一个加载动画；AI生成在局部面板显示“正在拾起成长的片段”或“正在整理建议”，不填虚假百分比。原型动画条为等待示意，正式版没有后端进度时改不定进度。用户可返回，正式持久任务只有在后端有任务查询能力后才可以承诺离开后保留结果。

错误说明原因与恢复动作，保持导航；表单错误保留草稿。登录过期与权限不足应使用专用文案，不能全部归为网络异常。toast仅用于复制、保存完成等轻反馈，约1.8秒。

弹层宽为375px屏减48px外边距（327px）；24px内边距；标题18px；正文13px/23；动作按钮44px高，间隙12px。解除结对说明对象与权限后果，按钮“取消 / 解除结对”。原生实现优先 `wx.showModal`，其视觉以微信系统为准。

## 7. 图标与插画

全部自制SVG，24×24网格、1.7px描边、圆端与圆连接。主要图标：幼苗、书页、记录笔、人像、总览四格、多人、箭头、警示、图片、分享、链接、盾牌、时钟、问号。tabBar23px，行图标20px，按钮图标18px，标签12px。

未选中使用文字色68%；选中主红，浅红7%填充作辅助手段。图标以真实语义搭配文字，关键操作不只有图标。原型不调用图标字体、不使用emoji或外部图标库。幼苗与印章是品牌点缀，不能作为状态含义的唯一载体。分享卡右下印章写“拾光育苗”，不仿造机构认证标章。

HTML内符号定义可作为前端导出图标的几何依据。小程序tab图建议导出81×81px PNG，保持相同轮廓与透明底，再按约23px展示；最终资源尺寸以当前微信文档与实机为准。

## 8. 数据与接口衔接

四维0–100；综合分为四维均值四舍五入。等级：`>=80 优秀`、`>=60 关注`、`>=40 预警`、`<40 高危`。单维提醒：`<40 高危`、`40–59 预警`、`60–79 关注`。本设计“需跟进”汇总只统计至少一维 `<60` 的孩子，`60–79` 留作日常引导；项目正式接口若采用其他统计口径，应先统一返回字段与文案。

### 8.1 需要工程对齐的缺口

以下是落地依赖，不代表已存在的后端能力：

1. **AI封面**：表有 `cover_url`，当前 poem 响应只有title/content。需接入真实图片生成、内容审核、存储、失败兜底与封面状态；可以先返回完整 poem 对象或生成后重新GET列表。原型没有调用图像生成服务，不能把SVG声称为AI图像。
2. **图片上传**：记录POST支持images URL数组，但文档无上传/删除/签名接口。需新增上传契约、压缩规格、失败重试与安全审核；不要让小程序持有存储管理员密钥。
3. **AI来源与长任务**：建议文档没定义generated_at、sourcePeriod、logIds、任务ID；正式展示时间与可恢复生成前需要明确接口。没有任务机制时只在当前页等待，退出提示取消或状态未知，不承诺后台完成。
4. **关系数量**：当前文档未定义每孩唯一主志愿者。原型简化为每孩一位主陪伴者，不据此新增数据库约束。若允许多对多，分配页应列“已有陪伴者”且可追加；展示与重复关系校验先按后端规则定稿。
5. **联系人、反馈与资料编辑**：文档没有可授权联系渠道、资料PATCH、反馈接口，因此原型使用信息说明弹层。正式版由组织提供联系人字段与反馈入口，不编造电话号码。
6. **内容安全与权限状态**：待定义审核中/未通过/登录过期/403/已解除结对/记录撤回的响应码与文案。前端不凭隐藏按钮代替权限校验。
7. **分数缺失**：评分代码的旧字段回退会将部分异常视为0。接口应明确“无观察”“有效0分”“计算失败”，UI不能自行猜测，以免产生假预警。
8. **退出与草稿**：原型内存草稿与blob图片在刷新后失效；正式版需定义草稿存储周期、退出清理、图片临时文件清理。敏感内容不进入无期限公共缓存。

## 9. 交互、动效与可访问性

点击反馈约120ms，页面入场不做复杂转场；局部加载允许1.4–1.5秒循环。不在每个卡片上添加入场动画。系统“减少动态效果”打开时停止装饰动画。图表和正文不依赖悬停。

主要可点区至少44×44px；36px筛选扩大透明热区，角标同理。图表图例使用标签+色点，预警使用文本+图标；图表提供文本值。读取顺序遵循从上到下。Web原型支持键盘焦点与模态焦点约束；原生无障碍属性与系统读屏另做实机验证。

## 11. 实现验收

1. 按服务器角色进入正确四项tab；志愿者通过深链、缓存或接口均无法看到未结对孩子。
2. 320/375/390/430px宽度及不同安全区无横向溢出、胶囊冲突或按钮遮挡；系统大字可阅读。
3. 关键路径：结对→档案→建议→记录；成长诗→生成→阅读→分享；总览→预警→档案；成员→分配→确认。
4. 预警人数、综合等级分布与平均分口径一致；趋势取真实周期，缺失不补零。
5. 每页加载/空/错误均有说明与下一步；表单失败保留输入；重复提交禁用。
6. 诗文和AI封面分别标记来源；封面失败可继续阅读；分享默认匿名且无分数和照片。
7. 相册拒绝、上传取消/失败、内容审核失败、登录过期、解除关系后的访问均能返回可用路径。
8. 视觉令牌、字体层级、圆角与SVG轮廓一致；没有emoji、外部图标字体、未声明的冷色。

本HTML为设计原型而非原生小程序代码；接口联调、内容安全、实际AI生成、发布运营、微信开发者工具与iOS/Android实机验收需要在开发阶段完成。
