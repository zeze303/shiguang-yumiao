# 拾光育苗 · UI设计交付

## 打开方式

直接用Chrome、Edge或Safari打开 `prototype.html` 即可；基础原型不依赖网络、构建工具或第三方库。

桌面左侧选择19个页面，中间是375×812设计画布，右侧是该页布局摘要。右上切换正常/加载/空态/错误。窄屏顶部提供页面下拉选择器。点击手机内的卡片、tabBar与按钮走实际演示流程。页面链接支持 `prototype.html#overview` 等首次定位。

Markdown规范用编辑器或Markdown阅读器打开；浏览器中点击规范链接可能直接下载，这是浏览器行为。

## 可交互的内容

- 志愿者与管理两套四项tab导航，19个主要/次级页面。
- 孩子列表筛选，管理搜索，详情四维雷达与可切维度的趋势节点。
- 开场话术复制，陪伴建议重新生成的等待演示。
- 对象/周期选择，成长诗等待、示例结果插入、阅读与匿名分享预览。
- 分享卡昵称显隐与SVG文件导出。
- 记录文字校验与计数，本机图片选择/移除/预览，最多3张，保存后列表置顶。
- 结对分配二次确认、取消不修改、解除二次确认；管理统计随演示数据变化。
- 每页四类状态共76个预览，错误后重试恢复表单选择与文字草稿。

## 设计边界

这是UI设计原型，不是真正原生小程序。所有身份、学校、分数、历史趋势、诗文与操作结果均为演示，不作为真实调研、上线或运营证据。AI建议与诗生成使用定时器展示示例，未调用业务后端；界面注明原型身份。

初始封面是自制SVG设计示意，不冒充AI图片。正式接口已有 `cover_url` 字段，但图片生成、审核与上传链路需补齐；详见规范8.1。真实AI封面补充时应单独保留来源说明，并与纯品牌插画区分。本次尝试生成AI封面未成功：当前服务返回模型 `gpt-image-2` 不兼容 Gemini native API 格式的400错误。未切换服务商或模型；交付不含真实AI封面，属于明确保留的落地项。

草稿与上传图片只保存在浏览器内存，刷新清空。不请求真实微信登录，不变更服务器结对关系，不发通知，不做公开发布。原型下载为SVG，正式小程序应Canvas导出PNG并处理相册权限。

## 验证记录（2026-10-12）

已在Hana内嵌Chromium浏览器打开本地HTTP原型并完成：

| 验证 | 结果 |
|---|---|
| 19页×4状态渲染 | 76项完成，无渲染异常 |
| 页面横向溢出、底部超出画布 | 375×812基准76项均无溢出 |
| 内容宽度320/375/390/430px | 19页各宽度，共76项无横向溢出（通过临时改变内容容器宽度测试） |
| 未填写记录提交 | 字段错误常驻，焦点定位文本域 |
| 记录错误状态→重试 | 保留已输入文字 |
| 记录保存 | 按钮禁用，完成后列表置顶，内存记录数增加 |
| 成长诗对象与周期 | 错误重试后选择保留，9月依据与10月不同 |
| 成长诗生成 | 进入阅读，新增对象与周期正确 |
| 分享昵称 | 默认匿名，可显式开启昵称 |
| 结对取消 | 不修改数据 |
| 结对确认与解除 | 选定志愿者生效，解除后恢复未结对 |
| 趋势财商节点 | 显示对应周期65分 |
| 管理搜索“小雨” | 仅匹配对应孩子 |
| 浏览器控制台 | 本轮检查无日志错误 |

尚需原生阶段验证：微信开发者工具、iOS/Android实际安全区、键盘、读屏、大字模式、上传审核、真实封面生成、相册拒绝与授权、后端权限和真实数据分页。上述桌面浏览器测试不能替代实机验收。

## 推荐演示

1. 我的结对 → 小禾 → AI陪伴建议 → 新增记录 → 记录列表。
2. 成长诗 → 生成 → 阅读 → 匿名分享卡 → 保存。
3. 管理总览 → 小川预警 → 档案 → 志愿者 → 为小雨分配 → 二次确认。
4. 切换一次加载/空/错误，再验证错误后的输入保留。

前端请先读 `design-spec.md` 的微信结构和接口缺口，再按 `page-spec.md` 实现。HTML中的桌面侧栏、黑色设备外框与右侧说明栏不属于小程序界面。
